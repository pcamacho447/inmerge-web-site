# Inmerge — Web App

React + Vite rebuild of the Inmerge marketing site (data consultancy, Lima, Perú), backed by a real Supabase backend for auth and the report catalog. **The site does not sell anything.** Premium reports are free in exchange for creating an account — the same lead-magnet logic the free reports always had, extended to the whole catalog. Real revenue comes from consulting quotes (WhatsApp/Contacto), not from the interface. A complete, hardened bank-deposit payment system still lives in this repo — migrations, an approval flow, a checkout modal — but nothing in the UI calls it; see "Pagos por depósito bancario — dormidos" below before assuming otherwise. This file is the source of truth for where things stand — read it before assuming anything about scope, decisions, or what's real vs. mocked vs. dormant.

## Origin — why this exists

The original design was a Claude-Design export (`.dc.html` files with proprietary `<x-dc>`/`<sc-if>`/`<sc-for>` tags and a `support.js` runtime that wasn't included) at `../front/` — those files cannot run as-is. This `app/` directory is a full rebuild in plain React 18 + Vite + react-router-dom, visually matching the original but with real HTML semantics, real CSS, and no proprietary runtime dependency. `../back/` is empty and unused — the real backend is Supabase, wired directly from this app (see "Modelo de negocio" below), not anything that would live in `../back/`.

## Stack & commands

React 18, Vite 5, react-router-dom 6, plain CSS + inline `style={{}}` objects (see "Styling convention" below) — no CSS-in-JS library, no Tailwind. `@supabase/supabase-js` is wired to a **real** Supabase backend (auth, the report catalog, and signed-URL downloads). Payments are also real _code_ — deployed migrations, a server-side approval function — but **dormant**: no page or route calls into that layer. See "Modelo de negocio" and "Pagos por depósito bancario — dormidos" below.

Run from this directory (`app/`), Windows/PowerShell — chain with `;`, not `&&`:

- `npm run dev` — dev server, default `http://localhost:5173/`
- `npm run build` — production build (also the fastest correctness check — catches JSX/import errors without a browser)
- `npm run lint` — ESLint (flat config, `eslint.config.js`)
- `npm run format` / `npm run format:check` — Prettier (140-char print width, chosen deliberately so the dense inline-style pattern below doesn't get exploded across dozens of lines)

## Styling convention

Inline `style={{}}` objects referencing CSS vars (`var(--terracotta)`), consistent across every component/page. Only cross-cutting concerns that inline styles structurally can't express live in `src/styles/index.css`: `@media` breakpoints, `@keyframes`, and — critically — **`:hover`/`:active` pseudo-classes**, via a small set of reusable utility classes applied alongside the inline style on interactive elements:

- `.btn-hover` — solid buttons (brightness lift + shadow on hover, scale-down press on `:active`)
- `.btn-outline-hover` — outline/ghost buttons (soft `--cream2` fill)
- `.card-hover` — cards (lift + shadow)
- `.row-hover` — list/accordion rows (background fill — this restores an effect the original `.dc.html` had via a proprietary `style-hover` prop that doesn't exist in plain CSS)
- `.link-hover` — text links (underline)
- `.icon-btn-hover` — icon-only buttons (soft circular fill)

These are deliberately built on properties the inline styles never set (`filter`/`transform`/`box-shadow`/`background-color`-as-fill/`text-decoration`) — a stylesheet `:hover` rule can never win against an inline style setting the _same_ property, so don't try to override `color`/`background` this way, it will silently no-op. All of them include `:active`, not just `:hover` — touch devices don't hover, so `:active` is what actually gives mobile users feedback.

When adding a new interactive element, apply the matching class. When converting a `<div onClick>` to a real `<button>`, remember to reset default button chrome inline (`border:'none', font:'inherit'` or explicit `fontFamily`/`fontSize`/`fontWeight` — **do not** use the `font` shorthand _after_ explicit `fontSize`/`fontWeight` in the same style object, it silently resets them back to browser defaults; this bug was made and caught once already).

### La trampa de CloudFront, para cuando exista `/reportes/:slug`

El despliegue va a **AWS S3 + CloudFront**, no Vercel/Netlify — coherente con que el dueño vende arquitectura sobre AWS. Esta app es una SPA de una sola página servida como estáticos: hoy todas las rutas cuelgan de `index.html` vía `react-router-dom`, así que un refresh o un enlace directo a cualquier ruta que no sea `/` **ya depende de que CloudFront sirva `index.html` en 403/404**, no solo un objeto S3 real. El Plan B (fuera de alcance de este plan) agrega `/reportes/:slug` como página propia — en cuanto exista, un enlace profundo a esa ruta devolverá 403 de S3 hasta que la distribución de CloudFront esté configurada para responder `index.html` cuando S3 devuelve 403 o 404. Es el error clásico de SPA-en-CloudFront. Ninguna configuración de CloudFront se hace en el código — es trabajo de infraestructura del dueño — pero muerde el día del despliegue, no antes, así que queda escrito acá donde se vea con anticipación.

Content/copy lives in `src/data/content.js`, not inline in JSX — includes `WA_LINK`/`waLink(message)` (prefilled WhatsApp text per CTA context), `SITE_URL` (**assumed** `https://inmerge.pe`, based on the `contacto@inmerge.pe` address already in the copy — the site isn't deployed and this hasn't been confirmed; also hardcoded in `public/sitemap.xml`/`robots.txt`/`index.html` — update all four together if it's wrong), `periodLabel()`, and `waVoucherMessage(order)` (prefilled WhatsApp text for sending the deposit voucher — still used by the dormant `CheckoutModal`, kept for when/if that flow reactivates). `PLAN_COPY` (marketing copy for the two paid plans) is **gone**, deleted with `/planes`. `REPORTS` and `PLANS` (the old static arrays) and any standalone pricing constants are **gone** — Supabase's `reports` table is now the only source (`src/hooks/useReports.js`); the `plans` table still exists in the DB (dormant, see below) but nothing in the live UI reads it anymore. Downloading is centralized in `src/hooks/useReportDownload.js` — a shared hook (`{ downloadingId, downloadError, handleDownload }`) used by both `/reportes` and `/cuenta` so the same "Descargar" button logic doesn't drift between two copies.

`useDocumentHead({title, description, path, noIndex})` (hook) sets per-page title/meta/OG/canonical client-side — helps the browser tab and Googlebot (executes JS), does **not** help social-link-preview crawlers (WhatsApp/Facebook/Twitter don't run JS, always see the static tags in `index.html` regardless of which route was shared — true per-page social cards would need prerendering/SSG, which this app doesn't have).

## Modelo de negocio — reportes gratis con cuenta, ingreso por cotización

**Esto reemplaza el modelo anterior de esta sección** (rediseño 2026-08-06; spec: `docs/superpowers/specs/2026-08-06-rediseno-portafolio-consultoria-design.md`). El sitio dejó de vender reportes y suscripciones. Free y premium ahora son la misma oferta — cualquier reporte publicado (`published_at` no nulo y no futuro) se descarga con solo tener una cuenta, sin pagar nada. El ingreso real de Inmerge viene de cotizaciones de consultoría iniciadas por WhatsApp/`Contacto.jsx`, no de un checkout. `Registro.jsx` sigue pidiendo persona-natural-vs-empresa + RUC condicional, pero ese dato ahora es para el perfil de facturación de una futura consultoría contratada — ya no hay compra de reporte que facturar.

La confirmación de correo está **desactivada** en el proyecto Supabase. `signup()` (`src/lib/auth.jsx`) deja sesión iniciada de inmediato — no devuelve nada en éxito — y quien la llama navega directo a `/cuenta`; no existe la pantalla "revisa tu correo". Un correo ya registrado sigue devolviendo éxito sin sesión (comportamiento de GoTrue, a propósito, para no revelar qué direcciones tienen cuenta); `signup()` detecta ese caso (`!data.session`) y lo convierte en el error accionable `'Ese correo ya tiene una cuenta. Inicia sesión con tu contraseña.'`, para que el usuario no se quede mirando un formulario que "funcionó" sin llevarlo a ningún lado.

`has_access(uuid, uuid)` se redefine en **`migrations/0013_access_is_free_with_account.sql`** — no en `0009` como decía una versión anterior de este archivo. Colapsa las tres ramas anteriores (gratis / compra / suscripción) en una sola: `p_user_id is not null` (hay sesión) y el reporte tiene `published_at` no nulo y `<= now()`. Las ramas de compra y suscripción se **eliminaron del cuerpo de la función**, no se dejaron muertas pero alcanzables — una rama inalcanzable miente sobre lo que el sistema hace. Si algún día vuelve a cobrarse, la versión anterior de la función está en `0009_published_and_file_path.sql` y en el historial de git; la columna `reports.tier` se conserva para poder distinguir sin una migración de datos, pero ya no gatea nada. EXECUTE sigue siendo solo para `service_role`.

`buildUser` en `src/lib/auth.jsx` ya no hace ningún round-trip a `subscriptions`/`purchases`/`orders` para construir el usuario — nada en `src/pages`/`src/hooks` lee `user.orders`/`user.ordersError`, y `user.subscription`/`user.purchases` solo se llenan desde `localStorage` cuando `VITE_DEMO_MODE=true` (ver la sección de pagos dormidos abajo), nunca desde una lectura real a la base de datos. `hasAccess()`, `isSubscriptionActive()` y `cancelSubscription()` se **borraron** de `auth.jsx` — ya no hacen falta porque ninguna página decide el acceso: lo decide `has_access()` del lado del servidor al momento de la descarga, dentro de la Edge Function.

Archivos borrados con este cambio: `src/pages/Planes.jsx`, `src/hooks/usePlans.js`, `src/lib/auth.test.js` (cubría exactamente la lógica de entitlements que se eliminó). Archivo nuevo: `src/hooks/useReportDownload.js` (ver arriba). La suite de Vitest bajó de 28 a 19 tests en 4 archivos (`formatPEN.test.js`, `orders.test.js`, `CheckoutModal.test.jsx`, `useReveal.test.jsx`) al desaparecer `auth.test.js`.

## Pagos por depósito bancario — dormidos, no eliminados

**Esto es lo más importante de esta sección.** Las migraciones `0003`-`0012`, `approve_order()`/`preview_order()`/`revoke_order()`/`reject_order()`, `src/lib/orders.js` y `src/components/CheckoutModal.jsx` **siguen existiendo y siguen funcionando** — compilan, y sus tests (`orders.test.js`, `CheckoutModal.test.jsx`) siguen en la suite y pasando. Pero **ninguna página ni ruta los usa**: `App.jsx` no monta `CheckoutModal` en ningún lugar, y lo único que lo importa fuera de su propio archivo es `CheckoutModal.test.jsx`. Es un sistema de pagos completo y endurecido (ver la auditoría de seguridad más abajo) que hoy nadie llama.

Sin esta declaración explícita, el próximo lector —persona o agente— va a encontrar ese sistema completo y asumir que el sitio cobra. **No cobra.** Todo el relato de fases (B0-B5) y la auditoría del 2026-08-04 más abajo son historia real de cómo se construyó y endureció ese sistema, no ficción — pero describen una capa que hoy está **dormida**, reemplazada por el modelo de arriba en `0013`.

Si algún día se reactiva: **hay que re-verificarla antes de confiar en ella.** Va a llevar meses sin ejercitarse con tráfico real — no asumas que "sigue funcionando" solo porque el código no se tocó y los tests pasan; los tests corren contra mocks, no contra un depósito real ni una `service_role` key vigente el día que se reactive.

`DEMO_MODE` (`src/lib/demoMode.js`, env `VITE_DEMO_MODE`) sigue existiendo para demostrar ese checkout dormido sin depositar de verdad: con la bandera prendida, `subscribe()`/`purchaseReport()` en `auth.jsx` escriben estado simulado a `localStorage`; con la bandera apagada (el default, y lo que corre hoy porque no hay ninguna ruta que las llame de todos modos) cada una revienta si se invoca, para que nunca conceda acceso falso en silencio. El banner "Vista previa de producto" en `CheckoutModal.jsx` solo se muestra con `DEMO_MODE` prendido — no lo borres, es lo que evita que una demo futura de esa UI parezca un cobro real.
